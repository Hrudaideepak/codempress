# Codempress Editorial Style Guide

**Version:** 1.0

> This guide establishes the editorial standards for every lesson,
> project, assessment, article, and AI-generated artifact published on
> Codempress. Its purpose is to ensure consistency, clarity,
> accessibility, and a high-quality learning experience.

------------------------------------------------------------------------

# 1. Editorial Principles

Every piece of content should be:

-   Accurate
-   Clear
-   Concise
-   Consistent
-   Inclusive
-   Practical
-   Action-oriented

Always teach **why** before **how**, and **concepts** before
**implementation**.

------------------------------------------------------------------------

# 2. Writing Style

Use:

-   Active voice
-   Short paragraphs
-   Clear headings
-   Bullet lists where appropriate
-   Simple language for beginners
-   Technical precision for advanced learners

Avoid:

-   Unexplained jargon
-   Long, dense paragraphs
-   Marketing language
-   Ambiguous terminology

------------------------------------------------------------------------

# 3. Audience Levels

Write for four audiences:

### Level 1 --- Beginner

Explain every new term.

### Level 2 --- Intermediate

Assume basic programming knowledge.

### Level 3 --- Advanced

Focus on architecture, optimization, and trade-offs.

### Level 4 --- Professional

Use industry terminology and production scenarios.

------------------------------------------------------------------------

# 4. Lesson Structure

Every lesson should follow this order:

1.  Learning Objectives
2.  Motivation
3.  Concept Explanation
4.  Visual Explanation (if useful)
5.  Examples
6.  Hands-on Practice
7.  Common Mistakes
8.  Best Practices
9.  Summary
10. Quiz
11. Interview Questions
12. Further Reading

------------------------------------------------------------------------

# 5. Terminology Standards

-   Use official language and framework terminology.
-   Define acronyms the first time they appear.
-   Use the same term consistently throughout a lesson.
-   Prefer widely accepted industry terms over informal alternatives.

------------------------------------------------------------------------

# 6. Formatting Standards

-   One H1 per document.
-   Use H2 for major sections.
-   Use H3 for subsections.
-   Use numbered lists for sequences.
-   Use bullet lists for collections.
-   Highlight important notes consistently.

------------------------------------------------------------------------

# 7. Code Style

Every code sample should include:

-   Title
-   Purpose
-   Complete source code
-   Expected output
-   Explanation
-   Common mistakes
-   Suggested improvements

Code should compile or run using supported versions.

------------------------------------------------------------------------

# 8. Diagram Standards

Diagrams should:

-   Explain relationships clearly.
-   Use consistent naming.
-   Avoid unnecessary decoration.
-   Include captions where needed.
-   Be readable on desktop and mobile.

------------------------------------------------------------------------

# 9. Accessibility Standards

Ensure:

-   Descriptive headings
-   Meaningful alt text for images
-   Sufficient color contrast in visuals
-   Keyboard-friendly interactions
-   Plain-language explanations for complex ideas

------------------------------------------------------------------------

# 10. Editorial Review Checklist

Before publishing, verify:

-   Grammar and spelling
-   Technical accuracy
-   Consistent terminology
-   Logical progression
-   Functional code
-   Correct links
-   Appropriate difficulty
-   Accessibility compliance

------------------------------------------------------------------------

# 11. Versioning

Track:

-   Author
-   Reviewer
-   Review date
-   Version
-   Major changes
-   Editorial notes

------------------------------------------------------------------------

# 12. Definition of Done

Editorial approval requires:

-   Style compliance
-   Technical approval
-   Accessibility review
-   Formatting review
-   Metadata validation
-   Changelog update
