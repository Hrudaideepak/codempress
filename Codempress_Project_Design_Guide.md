# Codempress Project Design Guide

**Version:** 1.0

> This guide defines the standards for designing projects within
> Codempress. Every project should reinforce learning outcomes, simulate
> real engineering work, and contribute to a learner's portfolio.

------------------------------------------------------------------------

# 1. Philosophy

Projects are not assignments---they are evidence of competency.

Every project should:

-   Solve a realistic problem.
-   Reinforce previously learned concepts.
-   Produce a portfolio-quality artifact.
-   Encourage engineering thinking.
-   Be reviewable by humans and AI.

------------------------------------------------------------------------

# 2. Project Hierarchy

``` text
Career
 └── Domain
      └── Module
           └── Project
                ├── Tasks
                ├── Milestones
                ├── Deliverables
                ├── Rubric
                └── Portfolio Evidence
```

------------------------------------------------------------------------

# 3. Project Levels

  Level   Type                 Typical Duration
  ------- -------------------- ------------------
  1       Micro Project        30--60 minutes
  2       Mini Project         2--6 hours
  3       Module Project       1--3 days
  4       Integrated Project   1--2 weeks
  5       Capstone Project     2--6 weeks

------------------------------------------------------------------------

# 4. Standard Project Template

Every project must include:

-   Project ID
-   Title
-   Summary
-   Difficulty
-   Estimated Duration
-   Prerequisites
-   Learning Outcomes
-   Business Scenario
-   Functional Requirements
-   Non-functional Requirements
-   Deliverables
-   Stretch Goals
-   Evaluation Rubric
-   Portfolio Value
-   AI Mentor Guidance

------------------------------------------------------------------------

# 5. Learning Outcome Alignment

Every requirement should map to at least one learning outcome.

Example:

-   Build REST API → Backend fundamentals
-   Deploy application → Cloud fundamentals
-   Write tests → Software quality

------------------------------------------------------------------------

# 6. Milestone Structure

1.  Planning
2.  Environment Setup
3.  Core Implementation
4.  Testing
5.  Deployment
6.  Documentation
7.  Reflection

------------------------------------------------------------------------

# 7. Deliverables

Projects should produce:

-   Source code
-   README
-   Architecture diagram
-   Screenshots or demo
-   API documentation (if applicable)
-   Test report
-   Reflection document

------------------------------------------------------------------------

# 8. Evaluation Rubric

Evaluate on:

-   Correctness
-   Code quality
-   Architecture
-   Maintainability
-   Documentation
-   Testing
-   Performance
-   Security
-   Accessibility (where relevant)

Use a transparent scoring rubric.

------------------------------------------------------------------------

# 9. AI Mentor Responsibilities

The AI mentor can:

-   Clarify requirements
-   Review code
-   Detect common issues
-   Recommend improvements
-   Explain feedback
-   Suggest extensions

The AI should coach rather than provide complete solutions by default.

------------------------------------------------------------------------

# 10. Portfolio Standards

A portfolio-ready project should include:

-   Live demo (when possible)
-   Public repository
-   Technical documentation
-   Design decisions
-   Lessons learned
-   Future improvements

------------------------------------------------------------------------

# 11. Review Workflow

``` text
Design
  │
Internal Review
  │
AI Validation
  │
Pilot Run
  │
Quality Assurance
  │
Publish
```

------------------------------------------------------------------------

# 12. Definition of Done

A project is complete when it has:

-   Approved specification
-   Working implementation
-   Passing validation
-   Complete documentation
-   Evaluation rubric
-   Portfolio guidance
-   AI mentor metadata
-   Version history
